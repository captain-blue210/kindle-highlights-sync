# Issue #30: 書籍不足のASIN単位調査

調査日: 2026-10-11（日本時間）。修正前: `6142686`。

## 確認できた取得不足の経路

日本のAmazon Notebookは、ページ本体の読込後もJavaScriptで一覧の追加ページを順次取得する。従来の一覧取得は `did-finish-load` から5秒後のDOMを読み、追加読込の終端を確認していなかった。

Chromeで開いていた日本リージョンのNotebookを再読み込みしたところ、次の変化を観測した。時刻はDOM観測時点であり、Electronの `did-finish-load` からの経過時間ではない。

| 日本時間 | 書籍行 | 読込中表示 |
| --- | ---: | --- |
| 12:34:34.605 | 14 | 表示 |
| 12:34:39.483 | 148 | 表示 |
| 12:34:45.384 | 194 | 表示 |
| 12:34:54.573 | 256 | 非表示 |

148件の観測時点には、その後現れた108 ASINがまだ一覧に存在しなかった。例えば `B0BJZNNS6W`、`B076C5KJ7P`、`B08DR7YL5J`。この差分は一覧描画段階にあり、注釈の取得失敗や保存保留とは別である。成熟した同じDOMに両版のASIN・タイトル抽出条件を当てた結果は、ともに256件、解析除外0件だった。

12:36:17.622の終端確認では、一覧の継続トークン要素41個のうち、先頭40個は非空、末尾だけが空だった。読込中表示は `display: none`、読込エラーには `aok-hidden` が付いていた。過去ページのトークンはDOMに残るため、全トークンが空になる条件は使用できない。

Amazonの[公開配信スクリプト](https://m.media-amazon.com/images/S/sash/q0N4m9rh8DW3T9s.js)を、実行せずに読み取った。`loadLibraryPane` が開始トークンを読み、`fetchAndAppendNextLibraryPage` が次ページを追加して繰り返す。終端で読込中表示を消し、取得失敗時には別のエラー表示を出す構造だった。取得したファイルのSHA-256は `3e1bf35eb64d12bd9839599cb934c29e470f697768de8eb1b0344f77df507ca8`。

hadynz版は[一覧取得](https://github.com/hadynz/obsidian-kindle-plugin/blob/2639ea1f8b9a8984d9d6814f255895c641529106/src/scraper/scrapeBooks.ts)で30秒待つ。[ローダー](https://github.com/hadynz/obsidian-kindle-plugin/blob/2639ea1f8b9a8984d9d6814f255895c641529106/src/scraper/loadRemoteDom.ts)も固定待機であり、全件を保証する仕組みではない。[差分選別](https://github.com/hadynz/obsidian-kindle-plugin/blob/2639ea1f8b9a8984d9d6814f255895c641529106/src/sync/syncAmazon/index.ts)より前の一覧との比較が必要である。

全ASIN集合と時点別集合は、ローカルの `diagnostics-local/issue-30-evidence.json` に保存した。このディレクトリはGit対象外。

## 修正内容と #29 との関係

- 一覧ではAmazon自身の追加読み込みを待ち、読込中表示の消失・末尾トークンの空・読込エラーなしを確認して解析する。件数の安定だけでは完了にしない。
- 既知の完了条件が60秒以内に確認できない場合は「取得範囲未確認」、エラー表示、通信失敗、途中のウィンドウ終了が起きた場合は「読込失敗」として記録する。観測済みの一覧と経過は中断時にも保持する。この場合は注釈取得・ノート保存に進まない。
- ASINで一覧を重複排除し、ASIN欠落・タイトル欠落・重複行を理由付きで記録する。欠落行がある同期は部分成功として報告する。
- 一覧ASIN、解析済みASIN、除外行、注釈取得成功／失敗ASIN、ノート保存の作成／更新／保留／失敗／新規ハイライトなしを別々に残す。
- 同期ごとに `.obsidian/plugins/kindle-highlights-sync/diagnostics/<開始日時>.json` を保存する。Cookie、継続トークンの値、Amazon HTML、ハイライト本文は含めない。保存不能時は通知し、直近の診断結果を `lastSyncDiagnostics` に保持する。

一覧の完了判定は #29 と共通の修正である。重複ASINの既存ノートや旧ID衝突を自動で解消する変更は含まない（#34、#33）。Clippings、過去の蓄積ノート、今回の保存件数はクラウド一覧集合と同一視しない。54冊の固定上限は使用しない。

## 検証と未完了の確認

遅延して148件から256件になるHTMLを使い、5秒では取得を返さず、終端で256件を返す回帰テストが旧実装で失敗し、修正後に通ることを確認した。末尾トークン非空、トークン／読込中表示の欠落、読込エラーのケースも検証する。

統合テストは実際の一覧ローダー・パーサー・Kindle API・ノート保存処理を通す。5秒を過ぎて現れるASINを取得／保存し、変更済みファイル名、保存済みID、内部リンク、旧アンカー、手編集、個人メモを保持する。連続2回の同期で重複追加しない。

`npm test`: 13ファイル・116テスト成功。`npm run build`: 型チェックと本番ビルド成功。独立レビューで追加の重大問題なし。レビューで指摘された通信失敗の分類、途中中断時の診断保持、部分成功画面のテストを補強した。

**実Amazon上の修正後同期、および両プラグインを同じアカウント・近い時点で独立実行した取得結果の比較は未実施。** Chromeの同じDOMに抽出条件を適用した比較と、プラグインを実行した比較は区別する。昨日の148／149件の全ASIN集合は保存されておらず、今日の256件との差を昨日の不足集合として断定できない。既存ノート数237とも一致させない。

次の実機検証では、修正版を適用して2回同期し、生成した診断JSONと同期前後のノートを比較する。hadynz側は保存処理を実行せず、差分選別前のクラウド一覧ASIN集合を同じ条件で記録して照合する。それが完了するまでIssue #30を完了扱いにしない。
