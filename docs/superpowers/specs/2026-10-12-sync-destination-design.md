# Issue #34: explicit duplicate-ASIN destinations

Base: origin/main c08c758; latest Issue #34 fetched 2026-10-12.

Resolve destinations separately from annotation identity/append logic (#33). For duplicate ASINs, present every path in the output directory in a command/settings modal. Require an explicit selection and Save. Save `noteDestinations[asin] = {path, ctime, invalidated?}` in plugin data.json; do not modify note properties to mark a destination. ASIN discovery reads configured/historical ASIN properties independently of bookId/title, including ASIN-only notes. Selection confirmation re-reads the chosen file and checks ASIN and creation time against the preview, then persists before enabling it. Provisional selections stay outside committed settings; queued settings saves merge the committed destination table at execution time. Pending selections also receive rename/delete invalidation.

An unselected duplicate is held. An existing selection always takes precedence over ASIN/book-ID fallback, including when only one/no candidate remains. Missing file, ASIN removal/change, replacement creation time, or invalid selection is held with candidates and a stable reason. Rename/delete events invalidate selections (also folder descendants) synchronously and persist the invalidation. Renames require explicit reselection, even if the note returns to its former path. Creation time guards missed events while unloaded; changed/unknown creation time requires reselection. No automatic merge/delete/rename, and no guessed relocation.

The resolver returns existing {path, content}, new, or held {reason, candidates, selectedPath?}. The writer uses the existing syncNoteContent inside atomic process and rechecks selected ASIN/ctime/invalidation there. Vault IO pins TFile objects from scan through process so path reuse during synchronization fails closed. Unselected files receive no process/create/write calls and stay byte-for-byte unchanged. Annotation matching/rendering remains unchanged for #33.

Outcomes keep status=held, reason, candidates, optional path; tracker reports held, diagnostics retain readable reason and candidate paths, never completion. Modal confirmation is blocked during sync; stale preview or failed persistence leaves selection unchanged. Invalid stored entries are kept as invalid tombstones, never dropped into automatic fallback.

Verification: full baseline; tests for duplicate candidates, pending, explicit selection, reload, loss/ASIN change, rename/delete/folder rename/path reuse, stale confirmation and failed persistence, two saves, resume after hold, exact unselected preservation, atomic races, customized property names/history; modal DOM check; typecheck/build/full suite. Real vault is untouched. #33 combined verification remains before merge.

Persisted path plus creation time is a conservative identity check, not a permanent filesystem identifier: replacement while the plugin is unloaded that preserves both values cannot be distinguished. Same-session TFile replacements are rejected even with identical creation time. Real Obsidian event ordering and timestamp-preserving offline replacement are not validated here.
